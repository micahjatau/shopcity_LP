# Prototype deviation registry

Approved deviations from the `410ecd75`/`figmaExport` prototype reference.

| Surface               | Deviation                                                                                                         | Reason                                                                                                        | Replacement / guardrail                                                                         |
| --------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Customer registration | The production form does not collect birthday, marketing consent, loyalty consent, or consent version.            | These fields are not supported by the production registration contract and must not be invented or discarded. | The registration flow exposes only supported customer and initial-card fields.                  |
| Capture Purchase      | The prototype-only Till/cashier-reference input is omitted.                                                       | No supported production property exists for this value.                                                       | No value is collected, stored, or silently discarded.                                           |
| Transactions          | The production view does not claim complete transaction history or add unsupported pagination.                    | The available transaction contract is bounded and detail-oriented.                                            | Copy identifies bounded scope; detail and immutable reversal remain backend-authoritative.      |
| Cashier workflows     | Prototype policy, customer-detail, ledger, draft, and sync cards are omitted.                                     | They duplicate or overstate backend state and create visual drift.                                            | Required state appears in the approved notice, status, review, confirmation, and success slots. |
| Operational shell     | Some prototype desktop context is represented as accessible metadata or behavior rather than additional geometry. | Session, connectivity, RBAC, logout, and responsive behavior must remain authoritative.                       | Shared shell primitives preserve behavior without adding unapproved desktop panels.             |
