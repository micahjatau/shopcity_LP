## Implementation status

The additive application schema, guarded POST endpoint, durable invocation records, and handlers for F0–F10 are implemented locally. F3 SMS delivery, F5 report-refresh processing, F6 delivery-report polling, and F10 cross-event outbox recovery delegate to existing worker logic; focused test coverage and Preview evidence do not yet establish that every handler is safe for rollout. Therefore this report does not validate the complete F0–F10 design and no Cron schedule is eligible for activation.

## Required Preview evidence before any cutover proposal

1. Restore authenticated Supabase CLI access and verify the exact Preview project ref independently of Production; verify Vercel project/environment/tier without printing credentials.
2. Validate the additive migration against a disposable local PostgreSQL/Testcontainers database (fresh install and upgrade from the current schema); confirm no destructive statements or data rewriting.
3. Complete isolated tests for all F0–F10 handlers, authentication/environment rejection, duplicate invocation, concurrent claims, stale lease recovery, retries/dead letters, event-type isolation, and financial/SMS invariants.
4. Deploy API code to Preview with a dedicated Preview scheduler secret and provider in a proven non-sending configuration. Prove that no external SMS call can occur.
5. Enable only Preview schedules after recording their exact cadence/owner and confirming the matching legacy worker flow is stopped. Verify schedule inventory from Supabase and Vercel.
6. Observe at least one complete operational cycle and repeated/overlapping dispatches; retain `ScheduledJobRun`, pg_cron/pg_net transport records, domain-state checks, redacted logs, report cursor progression, report freshness, and oldest-outbox-age evidence.
7. Exercise a safe failure and recovery scenario, prove a failed/ambiguous request does not cause duplicate financial/notification effects, and verify rollback to one scheduler owner.
8. Publish a refreshed report listing pass/fail/evidence references and unresolved risks. Do not activate Production schedules from this change.

## Unresolved release blockers

- Supabase CLI access is blocked by an invalid token. Local link metadata points to a candidate Preview ref, but remote project identity/schema/history and Preview schedule inventory are not verified.
- Vercel team plan is confirmed Hobby. The Hobby personal/non-commercial restriction is a deployment blocker unless the owner confirms eligibility or upgrades; Fluid Compute/runtime limits remain unverified. Supabase Cron cadence is separate from Vercel Cron, but the API still runs on Vercel.
- Flow adapters F0–F10 are not yet covered by isolated and Testcontainers tests; no Preview behavior is verified.
- Provider-side SMS idempotency/reconciliation after an ambiguous timeout is unresolved; this is a hard block for SMS Cron cutover.
- Exact flow frequencies, ownership, monitoring thresholds, and schedule-secret rotation procedure need operational approval.
- Report rebuild duration and serverless request budget have not been measured; current design intentionally limits F7 to one tenant per call.
- Migration and schedule setup have not been applied or validated against Preview.
