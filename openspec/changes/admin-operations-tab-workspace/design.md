## Context

`/admin/operations` is a route-backed page inside the Admin shell. It currently mixes `PilotHealthPanel`, `ReportsWorkspace`, seven partial route links, generic notes, three static badges, a generic info alert, and a link back to `/admin`. The Admin Reports route has a separate `OperationalReportsDashboard`; the Operations page already embeds `ReportsWorkspace`, which is the reporting content the new Reports tab should retain. The shared `Tabs` UI component renders static tabs but does not implement selection or keyboard behavior.

## Decisions

1. **Keep the page as a focused Admin workspace.** Preserve `/admin/operations` and its existing sidebar entry. Remove Users, Devices, Branches, Audit, and Adjustments from the shared Admin sidebar because they are available under Operations → Controls; register those five direct routes as aliases of the Operations navigation item so the shell's route allowlist still recognizes them. This keeps them off the visible sidebar while preserving Admin-only access and the correct active section.
2. **Use three page-local tabs.** Labels are Overview, Reports, and Controls. Overview is selected by default. Use local state; do not add URL state or cross-route persistence.
3. **Only mount the active panel.** This avoids loading the health and report endpoints for hidden tabs. Switching to Reports starts the existing report component; switching back may reload the health component as its normal lifecycle dictates.
4. **Overview reuses pilot health.** Render `PilotHealthPanel` in compact mode so its internal route row—including self-links and Supervisor destinations—does not duplicate Controls or expose cross-role navigation from this Admin workspace.
5. **Reports reuses the dedicated Reports-page type system and branch metadata.** Keep the existing Operations report data/actions, and place them under the established `.supervisor-reports-page` style scope only in the Operations Reports tab. Combine current-report/filter context with summary items in one result surface; show the report's populated fields as up to six human-labeled, correctly formatted columns, paginate rows, and open selected-item details in the existing closable dialog. Align numeric values to the right with tabular numerals, keep text/date values left-aligned, and allow horizontal table scrolling on narrow screens. Use **Summary items** as the card heading, show truthful filter context as quiet subtext (not a separate **Current filters** alert), and keep headings, table content, and supporting text on the Reports page type scale. For Operations only, populate the branch dropdown from the existing Admin-only, tenant-scoped branch-list endpoint; branch-scoped reports use the selected branch's persisted timezone automatically, and **All branches** sends no branch/timezone overrides. Keep the Supervisor Reports date-preset button treatment (**All dates**, **Last 7 days**, **Last 30 days**, **Custom dates**) with a responsive selector; All dates remains the default/no date override, while 7/30-day presets calculate boundaries in the branch timezone or the Supervisor default timezone. Custom dates validates an inclusive range before applying. Restyle the other filters with Supervisor Reports pill controls. Keep the Load report primary button's sidebar-matched red-orange gradient and preserve tenant-wide audit/pilot-summary behavior and status-badge removal. Do not change report options, data sources, other actions, role behavior, API contracts, or dedicated Admin/Supervisor routes.
6. **Controls links to existing dedicated workflows.** Use `/admin/users`, `/admin/devices`, `/admin/branches`, `/admin/audit`, and `/admin/adjustments`. Do not embed copies of those workflows or add new endpoints/routes.
7. **Use page-local accessible tabs.** The shared `Tabs` component has no selection callbacks or keyboard handling; avoid changing that shared component. Provide `tablist`/`tab`/`tabpanel` relationships, roving tab focus, ArrowLeft/ArrowRight, Home/End handling, and selected-state semantics locally.
8. **Remove the specified copy and static route-map furniture.** Keep a short page heading/description; remove the named badges, Back to admin, generic alert, and generic workspace notes.
9. **Match the main Admin Overview card surfaces in Operations Overview.** Add an opt-in `PilotHealthPanel` presentation variant: the outer health panel matches the Overview `.panel` (white, 1px `#e4e4e4` border, 16px radius, no shadow, 16px × 20px padding); each health signal tile matches `.metric` (same white/border/radius/no-shadow surface, 14px × 16px padding, 121px minimum height). Only the Operations tab opts in; the `CriticalFlowsPage` caller keeps the default style. Omit the header and per-signal `StatusBadge` pills in this variant while preserving the signal values, detail text, and grid behavior.
10. **Give Operations health-card supporting copy a clear type hierarchy.** Use 12px regular text, 1.45 line height, and readable secondary gray (`#676767`) for each signal's detail and the panel subtitle in the opt-in variant. Leave metric labels/values and default `PilotHealthPanel` callers unchanged.
11. **Add only summary information already returned by the existing API.** Use the current counts for a `Needs attention` summary, format `generatedAt` as the last-checked time, and show release version/short SHA plus the Sentry DSN configured flag. Keep missing values explicitly unavailable; don't treat them as zero. The endpoint returns a point-in-time summary, not history, so don't draw a trend chart or add an API contract under this scope.
12. **Keep the Operations result-table/dialog presentation opt-in.** Operations opts into the merged, paginated report table and selected-item dialog; the shared `ReportsWorkspace` default remains unchanged for every other caller. Its primary Load report action retains the sidebar-matched red-orange gradient; Supervisor Reports pill control styling is scoped to Operations filters and other report actions.

## Risks and mitigations

- Health fields may be unavailable; this change does not alter the health-data contract or repair existing metric semantics. Do not add new zero/sample values.
- `PilotHealthPanel` is also used by `CriticalFlowsPage`; the new presentation is opt-in so that test workflow retains its existing appearance, status badges, and subtext typography.
- `getPilotOperationsSummary` returns current counts and `generatedAt`, not a historical series. A trend chart requires a separately approved backend history/API change; never synthesize history from the current snapshot.
- Audit is actor-based lookup; the Controls card describes that behavior rather than promising a tenant-wide audit feed. The Reports workspace remains available both here and on the existing dedicated Reports route because the requested tab keeps the current Operations reporting content.
- Conditional tab mounting can reload data when users revisit a tab; it avoids unnecessary hidden-tab requests and adds no persistent cache.
- Tabs must remain usable by keyboard and narrow viewports; focused component tests cover selection, keyboard transitions, and routes.
