## Why

ShopCity needs a reliable provider option for ordinary SMS that accepts the fully rendered message body generated by the existing outbox. Africa's Talking documents a standard form-encoded SMS endpoint and a separate non-production simulator, so it can be integrated without converting ShopCity notifications into provider-managed templates.

## What Changes

- Add Africa's Talking as an explicitly selectable `SmsProvider`; preserve eBulkSMS as the default and leave Arkesel selectable.
- Send one rendered notification to one E.164 recipient using the standard `/version1/messaging` endpoint, API-key header, and registered sender ID.
- Add validated, provider-specific live and sandbox configuration, with production rejecting sandbox mode.
- Retain the matching provider message ID and record accepted submissions only as `SENT`.
- Document that Africa's Talking sends DLRs by callback and that callback ingestion is not included; without authenticated delivery evidence, messages remain `SENT`.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `sms-delivery-truthfulness`: explicitly select Africa's Talking and map provider acceptance to `SENT`, never handset delivery.
- `sms-operations`: document the standard send contract, message-reference handling, sandbox limits, and callback/DLR limitation.

## Impact

- Backend: `src/jobs/sms.provider.ts`, `src/jobs/sms.provider.factory.ts`, `src/config/env.validation.ts`, and focused provider/config tests.
- Operations: `.env.example`, `docs/runbooks/sms-operations.md`, and `docs/architecture/sms-and-otp-flows.md`.
- No database migration, business-template change, OTP change, frontend change, or live SMS request.
